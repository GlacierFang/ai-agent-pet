# 网关接入

> petd 要接的是**你自己那台** OpenClaw gateway —— 不是别人的、不是官方的。
> 这页说清楚：token 从哪拿、需要什么权限、填到哪里、接上之后 petd 到底在干什么。

## 这页是给谁的

| 你的情况 | 看哪 |
|---|---|
| petd 日志报 `gateway 连接失败` / `missing scope` | 下面「权限」和「排查」 |
| 想知道 petd 拿我的 gateway 干什么 | 「petd 用 gateway 做什么」 |
| 想换一台 gateway / 换端口 | 「怎么填」 |

## petd 用 gateway 做什么

只有三件事，全是读你的会话状态、往你的会话发消息：

| 用途 | 用到的 gateway 方法 | 需要权限 |
|---|---|---|
| 订阅会话列表，知道你正在跟谁聊天 | `sessions.subscribe` | `operator.read` |
| 拉会话状态，映射成宠物状态（idle / working / waiting） | `sessions.list` | `operator.read` |
| 确认卡把答案送回原来的会话 | `chat.send` | `operator.write` |

**petd 不读你的聊天内容全文来判断状态**，也不替你发任何你没点的消息。
`chat.send` 只有在你回答了确认卡时才会发一次。

## token 从哪拿

token 在 OpenClaw 的配置文件里：

```bash
python3 -c "import json,os;print(json.load(open(os.path.expanduser('~/.openclaw/openclaw.json')))['gateway']['auth']['token'])"
```

打印出来那串就是。**这是你的机器上的 token，不要贴到公开仓库、issue 或聊天里。**

> petd **不会**自动去读 `openclaw.json`。令牌有三个来源，优先级从高到低：
>
> 1. 你手写进 `petd/data/config.json` 的 `gateway.token`
> 2. 后台输入框填的 —— 落在 `petd/data/secrets.json` 的 `gatewayToken` 键
> 3. 环境变量 `PETD_GATEWAY_TOKEN`
>
> 后台填的比环境变量优先 —— 那是用户当下的一次明确动作。

## 权限

petd 连接时自报身份：

```json
{
  "client": { "id": "gateway-client", "mode": "backend" },
  "role": "operator",
  "scopes": ["operator.read", "operator.write"]
}
```

三件事必须对上，缺一个就被拒：

| 项 | 值 | 说明 |
|---|---|---|
| `client.id` | `gateway-client` | **白名单里的名字**，自造名字（`petd` / `my-client`）会直接 `INVALID_REQUEST` |
| `client.mode` | `backend` | 必须和 id 配对。`id=cli` + `mode=backend` 会被清空 scopes |
| `scopes` | `operator.read` + `operator.write` | 只读的话确认卡回不了程 |

**`operator.write` 是确认卡回程需要的。** 只给 `operator.read` 的 token，
握手能过，但用户选完选项答案送不回去 —— 表现为确认卡一直挂着。

### 你的 gateway 不给 write 怎么办

网关侧的 token 权限是**网关按 token 决定的**，petd 只能申请。
如果 petd 日志显示握手成功但 `chat.send` 报 `FORBIDDEN`：

1. 看 petd 实际发出的 scopes 是不是两个都在（后台「连接与诊断」页有原始遥测）
2. 看 gateway 侧的 token 是不是只授了 read —— 授 read-only 的 token 不可能凭空拿到 write

## 怎么填

三种都行，**填在哪都不影响权限**，gateway 认的是 token 本身。

### 1 · 环境变量（最简单）

```bash
export PETD_GATEWAY_TOKEN=把token粘这里
python3 -m petd --port 18860
```

### 2 · secrets 文件（适合开机自启）

```bash
mkdir -p petd/data
echo '{"gatewayToken": "把token粘这里"}' > petd/data/secrets.json
chmod 600 petd/data/secrets.json
```

### 3 · 后台填（不用重启）

后台 →「连接与诊断」→ 填**网关地址 / 令牌 / 端口** → 保存。

- 令牌落进 `petd/data/secrets.json`（权限 600），**不进 `config.json`** ——
  那是你会随手复制走的文件
- 网关地址或令牌改完**自动重连**，不用重启 petd
- 监听端口改动仍需重启 petd（那是监听地址，不是网关地址）
- 令牌留空 = 不改动，不会把已设的清掉

### 网关地址怎么填

默认 `127.0.0.1:18789`（OpenClaw gateway 的默认端口）。
gateway 在别的机器上时填 `IP:端口` 或 `ws://IP:端口`。

| 情况 | 填什么 |
|---|---|
| 同一台机器 | 默认值，不用改 |
| 另一台机器 | `192.168.1.50:18789` |
| 走反向代理 | `wss://你的域名` |

> ⚠️ **代理**：`HTTP_PROXY` / `HTTPS_PROXY` 环境变量会让本地 WebSocket 也走代理，
> 然后 gateway 收到 `403`。petd 默认**不走**代理；确实需要时在配置里开 `useProxy`。

## 接上之后

petd 日志出现这三行就算通了：

```
[petd] 监听 0.0.0.0:18860
[petd] 控制台 http://0.0.0.0:18860/admin/
... petd.gateway  gateway 已连接，scope=['operator.read', 'operator.write']
... petd.app      订阅到 N 个会话
```

`订阅到 N 个会话` 的 N 是你 gateway 里的会话数。
**N = 0** 说明连上了但没订阅到，检查 gateway 里有没有会话。

## 排查

| 症状 | 原因 | 怎么办 |
|---|---|---|
| `gateway 连接失败(403)` | 环境代理变量 | 清掉 `HTTP_PROXY`/`HTTPS_PROXY`，或配置里开 `useProxy` |
| `missing scope: operator.read` | id/mode 配对错 | 确认 `gateway-client` + `backend` |
| `INVALID_REQUEST`（握手就报） | client.id 是白名单外的名字 | 只能用 `gateway-client` |
| 握手成功但确认卡不回程 | token 只有 read | 需要 `operator.write` |
| `订阅到 0 个会话` | gateway 里没会话 | 随便开个会话再说 |
| 连上了但宠物不动 | 会话全是后台会话 | 后台会话不参与状态映射 |

更细的排查在 [故障排查](故障排查.md)。
