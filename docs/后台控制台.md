# 后台控制台

> 📘 设计与实现说明。v1 已实现；下方标注了现状与尚未接入的部分。

## 定位

**这是「我的宠物」面板。**

项目是私有化部署（见 [项目定位](项目定位.md)），单用户单设备 —— 没有账号、没有登录、没有多租户。petd 就是唯一的进程，页面挂在它的同一个端口上。

开源给各人部署后，这只宠物是**那个人的专属宠物** —— 所以页面的默认视角是「宠物在做什么」，不是「服务跑得怎么样」。技术遥测收进「连接与诊断」，不跟内容抢同一块屏幕。

## 形态

| 决策 | 理由 |
|---|---|
| 单页 HTML + 原生 JS | 页面只做「看状态 + 点按钮」，不值得引入前端构建链（node_modules / 前端 CI / 构建产物） |
| 挂在 petd 同一端口（`/admin/`） | **不多开一个端口** —— 少一个 systemd unit、少一份 nginx 配置、少一处端口冲突 |
| 后端接口与设备走同一套 WS | 预览就是**设备正在收到的那份字节流**，不是另渲染一遍 |
| 口令首次访问时设 | 没口令时后台是锁着的，第一次打开会让你设一个；设完存哈希 |

**关键红利**：预览与设备画面**必然一致**。因为整帧渲染在服务端完成，页面和屏看到的是同一份 JPEG 字节 —— 不会出现「后台好看、设备上丑」。

## 页面结构

六个页签，默认落在「我的宠物」：我的宠物 / 宠物库 / 宠物设定 / 连接与诊断 / 文档 / 使用说明。

### 1. 我的宠物（默认）

- **大字状态**：闲着 / 在忙 / 等你确认 / 刚做完 / 出错了 / 睡着了
- **跟进谁**：归因到具体会话（会话名，不是 key）
- **要不要你动手**：只有「需要你确认」和「有任务出错了」是高亮，其余是「不用你动手」
- **设备画面**：当前推给设备的 JPEG
- **会话列表**：全部会话，每条带状态、归因标记（「宠物在跟」）、相对时间
- **当前宠物**：当前用的是哪只宠物（封面是它的闲置图）+ 跳去宠物库
- **屏上在哪一层**：消息层（宠物本体）还是内容层（feature 卡片）—— 分层是整屏切换的，屏上永远只有一样东西

### 2. 宠物库

- 一只宠物一张卡，封面是它的**闲置图**；点卡片即设为当前
- 「＋新建宠物」永远在最后一张
- 新建 / 编辑都在同一个弹层里：起名字 + 六个格子各选一张 PNG
- 名字可以用中文
- **只有自建的宠物能编辑、能删除**；仓库自带的那只（默认宠物）两样都不行 —— 它是随版本走的底线，要改自己的宠物就新建一只

用户建的宠物存在 `petd/data/skins/`，**不进仓库**（gitignore）。仓库自带的存在 `skins/`。同名时用户那份优先。

**六态强制**：一套宠物要六种状态（闲置 / 干活 / 等你确认 / 刚完成 / 出错 / 睡着了）齐了才能设为当前 —— 屏上任何一刻都可能是六态中的任意一态，缺一态就等于那一刻屏上是空的。缺哪些在卡片上直接标出来。

### 3. 宠物设定

**宠物能做的，和做事的节奏。**

这一页分两拨。

**功能** —— 屏上会显示哪些内容。每个功能一张卡，卡上是个勾选框，勾上它就上屏轮播。卡里还带这个功能自己的设定项（会话功能带「优先显示哪个会话」，天气功能带「城市」，骰子功能带「模拟短按旋钮」）。

**功德箱**和**赛博骰子**也在这一栏里 —— 它们就是功能：勾上功德箱，屏上显示功德计数；勾上赛博骰子，短按旋钮才弹骰子。不勾就不出现。

（功德箱没干完过活的时候没话可说，那张卡不上屏 —— 有数字了才有。）

**主机**功能看的是运行 petd 的这台机器（树莓派或服务器）—— CPU、内存、磁盘、温度、开机时长。屏摆在客厅，主机塞在机箱里时，用它确认主机还活着。



**设置** —— 做事的节奏：每张卡停留多久、干完留多久、信息密度、睡觉时段。

改完立刻生效，也写进 `petd/data/config.json`（重启还在），并同步告诉设备（`setDensity`）。

> 📌 `petd/data/config.json` 不进仓库 —— 端口、宠物、睡觉时段都是每台机器自己的事，
> 不该跟着代码走。首次启动 petd 会自动生成一份默认的。

> 以前这里放的是一份「能力清单」（`petd/data/capabilities.json`），列的是旋钮动作 id。
> 那份的 `enabled` 字段**全仓没有任何地方读它** —— 勾掉了什么也不会发生。
> 一个骗人的清单比没有清单更糟，所以删掉了，换成这份每项都接得上代码的。

界面上是「一项一张卡，卡里用该用的控件」—— 勾选的勾选、选的选、填的填。时长让用户自己填数字，不给固定的几档。

**睡觉时段是特殊的一种**：它不是一个值，是**一段连续的区间**，所以卡里给的是一条 24 小时横轴。在轴上点一下定起点，再点一下定结束（落点对齐到 30 分钟），高亮的那一段就是睡觉时段，改完立刻生效。跨午夜在图上是首尾两段 —— 不会画一条穿过中间的连线骗人。下方读数给出起止时刻和时长（跨午夜会标出来）。

### 4. 连接与诊断

这页给「东西没按预期工作」的时候查。**安装的活儿在「使用说明」页** —— 四步指引、设备地址、配网说明都在那儿。

- 连接状态 + 原始遥测（`device.*` / `pet.*` / `frames.*` 共 26 项，默认折叠）
- 连接配置（网关地址 / 令牌 / 监听端口）—— 改完**要重启 petd**
- 诊断日志（SSE 实时 + 增量补拉）
- 旋钮手势（折叠区，列出当前映射：哪个手势对应哪个动作）

**渲染质量和帧率不在后台表单里** —— 屏只有 240×320，85 和 95 肉眼分不出；而帧率改完要重启才生效，放在页面上只会让人以为改坏了。真要调就改 `petd/data/config.json`。

### 5. 文档

**仓库里的文档直接在控制台里读** —— 左边分组列表，右边正文。

- **两组**：「给你用的」（部署手册、硬件指南、故障排查）/「给开发者看的」（后台控制台、协议、状态语义、旋钮、固件构建、美术规范、feature开发、项目定位）
- **没登记的新文档落进「其它」组**，不会消失 —— 省得以后加文档忘了登记
- 服务端渲染 markdown（`markdown-it-py`，纯 Python、无外部资源）—— 断网内网也能读
- 文档之间的相对链接在页内跳；指向仓库根的落到 GitHub

### 6. 使用说明

**这是说明书，不是进度页。** 它只讲「怎么用」，不讲系统现在什么状态。

四块内容：

1. **宠物怎么用** —— 旋钮手势表（哪个手势对应哪个动作）+ 信息密度三档
2. **屏上会看到什么** —— 两层互斥、六种表情、睡觉时段 + 全部内容卡清单
3. **设备怎么装上** —— 四步操作指南 + 设备地址
4. **后台能改什么** —— 宠物库 / 宠物设定 / 连接与诊断 三行指路

**手势表、密度档位、内容卡清单全部读服务端当前在用的配置** —— 写死一份的话，用户改了 `gestures.json` 之后说明页就成了骗人的。

四步每步带一个徽标（已完成 / 还没做），那是附注不是主体 —— 徽标的状态只到「设备连上没」这一级，因为服务端报不出更细的。

**登录前后都能看到**，但内容不同：

- **未登录**（口令页）：只显示四步快速指引和设备地址 —— 最需要这份指引的人正是还没配好的人，不能挡在门外
- **登录后**：完整的四块说明书

### 7. 「连接与诊断」页的细节

#### 连接配置

后台能在线改的只有「连接配置」那几项（网关地址 / 令牌 / 监听端口），改完**要重启 petd**才生效。

其余配置在 `petd/data/` 下，都是**随版本走的默认值**，手改文件后重启 petd 生效：

- `gestures.json` —— 旋钮手势映射（哪个手势对应哪个动作）
- `state_rules.json` —— 会话状态判定规则（gateway 字段 → 宠物状态）
- `config.json` —— 本机配置，**不进仓库**，首次启动自动生成

🟡 手势和状态规则没有做成在线编辑表单 —— 现在的「连接与诊断」页只把当前的手势映射列出来给你看。

#### 固件与更新

| 方式 | 手段 | 说明 |
|---|---|---|
| **本地固件** | `/admin/api/firmware` 列出 `firmware/build/*.bin` | 本地编译产物在仓库里时列得出来 |
| **下载 .bin** | 从 GitHub Releases 手动下载（`fw-v0.4.1`） | 🔴 后台的 Release 列表**未接入**（`/admin/api/releases` 返回空），页面给的是手动下载说明 |
| **USB 烧录** | 页面给出 `esptool` 命令行（Linux / Windows 各一条） | 烧录时**只接 PC**，不接充电头 |
| **无线升级** | —— | 🔴 **不支持 OTA**，固件只能 USB 烧录 |

**明确不做在线刷机**：ESP32-S3 DevKitC-1 两个 USB-C 的 5V 相通，在线刷机页面会诱导用户同时插 PC 和充电头 —— 硬件指南明令禁止。

#### 诊断

- petd 日志尾部
- gateway 连接与 scope 状态
- 渲染耗时直方图

#### 设备状态

| 项 | 说明 |
|---|---|
| 在线状态 | WS 连接是否建立、断线时间 |
| IP / mDNS 名 | 设备报上来的 |
| 固件版本 | 设备握手时上报 |
| 解码耗时 | 实测 TJpgDec 单帧解码 ms 数 |
| WS 帧统计 | 接收帧数、字节数、丢帧 |
| 旋钮事件流水 | 滚动显示最近 N 条原始事件（调手势时最有用） |

## 安全边界

- **只绑内网地址**（`127.0.0.1` + 局域网 IP），不监听公网
- 启动时打印一行提示，说明当前是「还没设口令」/「已启用口令」/「鉴权已关掉」
- **口令**：第一次打开控制台时设一个，设之前 `/admin/api/*` 全锁（401）；口令只存 scrypt 哈希，落盘 `petd/data/admin.json`
- **三种模式**：网页首设（存哈希）/ `PETD_ADMIN_PASSWORD` 环境变量（自动部署，明文在 env）/ `PETD_ADMIN_AUTH=off`（完全敞开，开发自跑）
- **两个例外是公开的**：`/admin/api/session`（问「要不要口令」）和 `/admin/api/setup/public`（未登录页的引导）
- `/admin/api/setup/public` 只给设备地址和配网说明 —— **设备编号、会话数、帧数一律不给**，那些是登录之后才该知道的东西
- 设备 WebSocket `/device` **不鉴权** —— 加鉴权要改固件，违反项目原则
- 共享锁，不是账号体系：没有注册、没有用户表、没有多账号

## 实现要点

- 静态文件挂在 `/admin/assets/`（`index.html` / `app.js` / `style.css`），**零外部 CDN 引用** —— 断网的内网也能用。
- 日志用 `GET /admin/api/events`（SSE）实时推送，页面另用 `/admin/api/logs?since=N` 补历史。
- 预览每秒带时间戳刷新，破浏览器缓存。
- **不支持 OTA 升级，也就没有 OTA 按钮** —— 固件只能 USB 烧录。
- **后台不是唯一入口** —— 屏上（旋钮）也能操作：切宠物、翻会话、翻页。看一眼就懂的东西放屏上，需要读懂内容的留后台。
- **口令框留在同一页** —— 不新增 `/admin/login` 路由、不跳页。
- **预览图初始用透明占位图** —— 静态 `src` 会在登录前就发请求，那时没有 cookie 会拿到 401。
