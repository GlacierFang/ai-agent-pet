# 部署手册

> 🟢 petd 服务端已落地并**实测跑通**（2026-11-03）。固件已在 CI 里用真实 ESP-IDF v5.5 编译通过，
> 但**尚未在真实硬件上验证**（硬件未采购）。
> 硬件细节见 [硬件指南](硬件指南.md)，协议见 [协议](协议.md)，后台页见 [后台控制台](后台控制台.md)。

## 你需要什么

| 类别 | 内容 |
|---|---|
| 硬件 | ESP32-S3-DevKitC-1 (N8R8)、2.4" ST7789 240×320、KY-040 旋转编码器 |
| 线材 | 杜邦线、排针 |
| 主机 | 一台跑着 OpenClaw gateway 的 Linux 机器（本项目在树莓派 4B 上开发） |
| 软件 | ESP-IDF v5.5.x（编译固件）、Python 3.10+（跑 petd） |

**不需要**：PCB 打板、焊接、示波器。

## 步骤 0 · 准备

1. 按 [硬件指南](硬件指南.md) 的 BOM 买齐三块料
2. **到货必测项 —— ⚠️ 先测再接线**：ST7789 的 8 针顺序、排针性别与杜邦线匹配、KY-040 每圈步数、抖动与回差
3. 装 ESP-IDF v5.5.x：`idf.py --version` 要有输出

## 步骤 1 · 先跑通 petd（不用硬件）

**先证明软件链路是通的，再碰硬件。** 这一步完全不需要实物。

```bash
git clone https://github.com/GlacierFang/ai-agent-pet.git
cd ai-agent-pet
pip install -r requirements.txt      # 或 pip install -e .
```

### 1a · 起 petd

```bash
python3 -m petd --port 18860
```

**预期输出**：

```
[petd] 监听 0.0.0.0:18860
[petd] 控制台 http://0.0.0.0:18860/admin/
... petd.gateway  gateway 已连接，scope=['operator.read']
... petd.app      订阅到 N 个会话
```

> ⚠️ **token 怎么给**：petd 依次找 `PETD_GATEWAY_TOKEN` 环境变量 → `petd/data/secrets.json`（key 是 `gatewayToken`）。
> 两者都没有时会显示 `gateway 连接失败(missing scope)` 或 `连接被拒`。

### 1b · 验证 petd 自己在工作

```bash
curl -s http://127.0.0.1:18860/admin/api/status
curl -s -o /tmp/p.jpg http://127.0.0.1:18860/admin/api/preview.jpg && file /tmp/p.jpg
```

**预期**：`status` 里 `gateway.connected=true`、`pet.sessions` 大于 0、`pet.state` 是某个状态名；`preview.jpg` 是 `JPEG image data ... 240x320`。

### 1c · 用 mock 设备跑通整条链路

没有硬件时，用 mock 设备代替真实 ESP32：

```bash
python3 petd/tools/mock_device.py --host 127.0.0.1 --port 18860
```

**预期**：

- 打印收到 `welcome`
- 持续收到 `frame` 文本预告 + binary JPEG，并回 `frameAck`
- 交互命令台：`r` 旋转、`p` 短按、`l` 长按、`h` 按住旋转、`q` 退出

再查一次 `/admin/api/status`，此时 `device.online` 应该是 `true`。

**出错查**：[故障排查](故障排查.md)

### 1d · 装成 systemd 服务（推荐）

开发时直接 `python3 -m petd` 就行，但要长期跑（比如放到公网入口后面），用 systemd 更稳：

```bash
cd ai-agent-pet
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

mkdir -p ~/.config/petd
cp deploy/petd.env.example ~/.config/petd/petd.env
chmod 600 ~/.config/petd/petd.env
# 编辑 petd.env 填入 gateway token

cp deploy/petd.service ~/.config/systemd/user/petd.service
systemctl --user daemon-reload
systemctl --user enable --now petd
```

```bash
systemctl --user status petd
journalctl --user -u petd -f
```

> ⚠️ **只能跑一个实例**。两个用同样 `client.id=gateway-client` 的 petd 会互相顶掉，
> 后启动的那个会被网关拒为 `NOT_PAIRED` / `DEVICE_IDENTITY_REQUIRED`。
> 换实例前先 `systemctl --user stop petd`。

> 💡 **pip 装不上？** 本机如果设了全局 `HTTP_PROXY`，PyPI 会 403。
> 这时用 `python3 -m venv --system-site-packages .venv` 复用系统已装的依赖即可。

## 步骤 2 · 让 petd 认到 gateway

petd 需要 gateway 的连接配方：**token + client.id=gateway-client + client.mode=backend + role=operator + scope=operator.read**。

🟢 配方已实测 —— 见 [状态语义](状态语义.md) 和 `petd/data/config.json`
（这份文件不进仓库，首次启动 petd 会自动生成一份）。

**预期**：终端打印 gateway 已连接 + 拿到 scope；`pet.sessions` 反映真实会话数（实测 6 个，后台会话已排除）。

> ⚠️ **本机连接必须绕过 egress proxy**：如果你的环境全局设了 `HTTP_PROXY`/`HTTPS_PROXY`，
> `websockets` 会把连 `127.0.0.1` 的请求也塞进代理 → `HTTP 403`。
> petd 默认 `gateway.useProxy=false`，走直连。

## 步骤 3 · 接线

按 [硬件指南](硬件指南.md) 接线。

**⚠️ 安全规则（不可违反）**：

- **烧录时只接 PC**，不接充电头
- **运行时只接充电头**，不接 PC
- **两个 USB-C 的 5V 是相通的** —— 同时接会烧板

## 步骤 4 · 编译与烧录固件

见 [固件构建](固件构建.md)。

```bash
cd firmware
idf.py set-target esp32s3
idf.py build
idf.py -p /dev/ttyACM0 flash
```

**不想装 ESP-IDF** → 从 [GitHub Releases](https://github.com/GlacierFang/ai-agent-pet/releases) 下 `fw-v0.2.0` 的 `.bin`，用 esptool 刷：

```bash
python3 -m esptool --chip esp32s3 --port /dev/ttyACM0 write_flash -z 0x0 merged-binary.bin
```

> ⚠️ 下 `fw-v0.2.0`，**别下 `fw-v0.1.0`** —— 那一版的 Wi-Fi 凭据是编译时写死的，CI 不注入，刷完连不上网。
> `fw-v0.2.0` 自带 SoftAP 配网页面，刷完填一下 Wi-Fi 就能用。

## 步骤 5 · 设备配网 + 找 petd

固件自带配网，**不需要编译，也不需要改代码**。刷完固件直接做这三步：

1. 设备开机后屏幕显示 `PETD SETUP`，下面有：
   - **热点名** `petd-setup-XXXX`（设备自己的）
   - **密码**（屏幕上的 8 位 PoP）
   - **配网页地址** `192.168.4.1`
2. 手机连上这个热点，浏览器打开 `http://192.168.4.1`
3. 在网页里填家里的 Wi-Fi 名称和密码 → 点「保存并重启」

设备重启后连上 Wi-Fi，再自己解析 `petd.local` 找到服务端（petd 起来时就在 UDP 5353 上广播它，纯标准库实现，不装 zeroconf）。

后台控制台的「使用说明」页有这四步的指引，每步带一个徽标 —— 但徽标只到「设备连上没」这一级，服务端报不出更细的。

### 配网出问题了

| 症状 | 怎么办 |
|---|---|
| 屏幕显示 `NO WIFI` | Wi-Fi 密码错了。重新进配网模式改密码 |
| 屏幕没反应（黑屏） | 固件没刷成功，按下面的「重进配网模式」操作 |
| 连上了但找不到 petd | 确认 petd 在跑；`getent hosts petd.local` 应能解析到 |
| 想改 WiFi 了 | 见下面的「重进配网模式」 |

### 重进配网模式（三个入口，缺一个就变砖）

| 方式 | 操作 |
|---|---|
| BOOT 键 | 断电，按住板上的 BOOT 键再上电 |
| 长按旋钮 | 开机后 8 秒内长按旋钮 5 秒 |
| 自动回落 | 连续连不上 30 次，设备自己回到配网模式 |

配好的凭据存在设备的 NVS 里（断电不丢），所以正常只需要配一次。

### 其它

- petd 侧 `/admin/api/status` 里 `device.online` 变 `true` 就是连上了
- 自测广播器：`python3 petd/tools/check_mdns.py`（退出码 0 = 通过）
- 不想广播就关掉：`petd/data/config.json` 里 `"mdns": {"enabled": false}`
  （这份文件不进仓库，首次启动 petd 会自动生成一份）

## 步骤 6 · 看到宠物动起来

**预期**：屏幕显示表情；转旋钮切会话；短按切页；长按刷新；按住旋转换信息密度。

## 步骤 7 · 后台控制台

打开 `http://<pi>:18860/admin/` —— 见 [后台控制台](后台控制台.md)。

> 💡 **第一次打开会让你设口令**。设之前后台是锁着的 —— 设完才进得去。
> 详见下面的「口令」一节。

### 7a · 挂到反向代理后面

后台页用的是**相对路径**，API 基址从 `document.baseURI` 推导 ——
所以挂到任何反代前缀下都不用改代码，只要前缀以 `/` 结尾。

```nginx
# 前缀不带斜杠也要能访问
location = /ai-agent-pet {
    proxy_pass http://127.0.0.1:18860/admin/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
location /ai-agent-pet/ {
    proxy_pass http://127.0.0.1:18860/admin/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_read_timeout 300s;
    proxy_send_timeout 300s;
    proxy_buffering off;   # SSE 日志流不能缓冲
}
```

> 💡 **验证要探根路径 + 至少一条子路径，并跟跳转链**：
> `curl -L --max-redirs 5 -o /dev/null -w '%{url_effective} %{http_code} %{num_redirects}\n'`。
> 只探子路径会漏掉「根路径自己会跳」这类问题。

> 💡 **路径前缀，不要子域名**。反向代理通常只绑一个 Host，子域名没有 DNS 解析会直接 503。

### 7b · 口令

**第一次打开后台会让你设一个口令。** 设之前后台的接口全是锁着的（401），设完直接放行。

- 口令**只存哈希**（scrypt），落盘在 `petd/data/admin.json`（权限 600，已在 .gitignore 里）
- **忘了就删掉那个文件**，重启 petd，会重新让你设一次
- 不做强度限制 —— 那是内网本地服务，不是公网系统；但**别把它设成 `123456`**
- 连错 5 次锁 30 秒 —— 挡一下本机上的暴力猜

三种模式：

| 怎么来的 | 行为 |
|---|---|
| 网页上第一次设（默认） | 存哈希到 `petd/data/admin.json` |
| `PETD_ADMIN_PASSWORD` 环境变量 | 自动部署用，明文存在 env 文件里（`chmod 600`） |
| `PETD_ADMIN_AUTH=off` | **完全敞开** —— 开发自跑用，局域网里人人能看 |

> ⚠️ `/device` 的 WebSocket **不鉴权** —— 固件约束，改不了。同网段的人可以推帧。
> 这是已知边界，见 [安全](../SECURITY.md)。

## 常见卡点

| 症状 | 去哪查 |
|---|---|
| `gateway 连接失败(403)` | 环境代理变量 → petd `gateway.useProxy` |
| `missing scope: operator.read` | client.id / client.mode 配对 |
| 屏幕全黑 | [故障排查](故障排查.md) · 黑屏 |
| 花屏 / 红蓝互换 | [故障排查](故障排查.md) · 花屏（字节序 / SPI 频率） |
| 设备连不上 | mDNS / Wi-Fi 配网 |
| 宠物不反映会话状态 | gateway scope / 状态映射 |
| 解码慢 / 掉帧 | SPI 频率、TjpgDec 档位 |

## 卸载

- 停止 petd
- 设备上电时按住 BOOT 进下载模式，用 esptool 擦除 flash
- 删除 `petd/data/` 目录
