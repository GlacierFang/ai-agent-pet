# 状态语义

petd 把 gateway 的会话状态映射成宠物表情。这是整个项目的**灵魂部分** —— 硬件谁都能拼，会话状态怎么变成表情才是要积累的东西。

> 🟢 本文所有字段名与取值均已一手实测（2026-11-03，OpenClaw 2026.10.8）。

## gateway 实测字段

`sessions.list` 每行（节选实际拿到的字段）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `status` | `"running"` / `"done"` / `"error"` / **键缺省** | 会话状态。**缺省等价于 idle** |
| `hasActiveRun` | bool | 此刻是否真有活动 run（区分「会话存在」和「正在跑」） |
| `unread` | bool | 有未读消息 |
| `permissionModePending` | bool | **等你确认/授权** |
| `abortedLastRun` | bool | 上一次跑被中断 |
| `isBackground` | bool | 后台会话（Automation/Cron 等） |
| `key` / `label` / `displayName` | string | 会话标识与显示名 |
| `lastActivityAt` / `updatedAt` | 时间戳 | 排序依据 |

⚠️ **没有** `thinking` / `working` / `waiting_user` 这些值 —— 那是别的项目的词表。照抄会全错。

## 映射表

| 宠物状态 | 判定条件 | 素材 | 表现 |
|---|---|---|---|
| `idle` | 无会话，或 `hasActiveRun=false` | `idle.png` | 闲置 |
| `working` | `status=running` 且 `hasActiveRun=true` | `working.png` | 埋头干活 |
| `waiting` | `permissionModePending=true` 或 `unread=true` | `waiting.png` | **举牌子（最醒目）** |
| `done` | `status=done` | `done.png` | 刚完成 |
| `error` | `status=error` | `error.png` | 出错 |
| `sleeping` | 无活跃会话持续 N 分钟 | `sleeping.png` | 睡着了 |

## 判定优先级

一个会话可能同时命中多条规则。**按这个顺序取第一个**：

```
waiting  >  error  >  working  >  done  >  idle
```

理由：**等你批准最急** —— 那是唯一会真正挡住你的事。出错次之（要处理，但不等人）。

## 宠物反应全部会话

宠物不是某个会话的指示器，是**这个人的桌面伙伴**。所以它反映**全部会话**：

- 每个会话各自判状态
- 宠物状态 = 最急的那个（同级取最近活动的）
- **归因**：`pet.attribution` 指出是哪个会话在起作用（后台会话列表里标「宠物在顾」）
- **计数**：各有几个在等。屏幕上写「等你 ×2」—— 处理完一个才发现还有一个，信任感就没了
- **焦点不改状态**：旋钮选中的会话只决定会话卡片看哪条，不改变宠物状态

```
counts = {"waiting": 2, "working": 1, "idle": 3}
```

## 时间戳单位

⚠️ gateway 给的 `lastActivityAt` 是**毫秒**。按秒算会出两个 bug：前端「几分钟前」全显示成「刚刚」，以及 done 衰减永远不触发（秒减毫秒是负数），几天前跑完的会话会一直让宠物停在「刚完成」。

`petd/state.py` 的 `epoch_s()` 在边界处统一：量级 > 1e11 视为毫秒，除以 1000。

## 状态抖动与稳态窗

**问题**：多会话并发、或后台任务（定时抓取 / 心跳）短时拉起又退出时，gateway 上报的会话列表会有瞬态脏状态（`status` 缺省、空 session）。如果 `idle` 只靠排除法判定，宠物会在 `idle` 和 `working` 之间**抽搐闪烁**。

**对策（三条一起用）**：

| 手段 | 规则 | 为什么 |
|---|---|---|
| 稳态窗（滞回） | 从 `working`/`waiting` 退回 `idle` 要**连续 3 秒**都判为非活跃 | 挡掉瞬态拉起 |
| 明确空集判定 | `idle` = 活跃会话列表为空 **OR** 所有会话非活跃已超 30 秒 | 不靠排除法兜底 |
| 事件去抖 | `sessions.changed` 事件 200ms 内合并处理 | 一次变更刷多条事件 |

**注意**：稳态窗只作用于**退回 idle**。进入 `working` / `waiting` / `error` 立即生效 —— 那些是需要人马上知道的状态，迟 3 秒不行。

实现上放 `data/state_rules.json`：

```json
"stability": {
  "idleAfterMs": 3000,
  "idleGraceMs": 30000,
  "eventDebounceMs": 200
}
```

## 状态抖动：稳态窗

多会话并发、或后台任务短时拉起又退出时，gateway 上报会有瞬态脏状态（`status` 缺省、空 session）。若 `idle` 只靠排除法判定，宠物会在 `idle` 和 `working` 之间抽搐。

**三条对策**：

| 手段 | 规则 |
|---|---|
| 稳态窗（滞回） | 从 `working`/`waiting` 退回 `idle` 需**连续 3 秒**都判为非活跃 |
| 明确空集判定 | `idle` = 活跃列表为空 **OR** 所有会话非活跃已超 30 秒 |
| 事件去抖 | `sessions.changed` 200ms 内合并 |

**稳态窗只作用于退回 idle。** 进入 `working`/`waiting`/`error` 立即生效 —— 那些要人马上知道，迟 3 秒不行。

## 多会话怎么选

同时有多个活跃会话时：

- 宠物状态取**最急**的那个（见上），同级取 `lastActivityAt` 最新的
- 旋钮可以在活跃会话间循环切换（见 [旋钮](旋钮.md)）—— 这只改会话卡片的焦点，**不改宠物状态**
- `isBackground=true` 的会话**不参与**宠物状态 —— 后台任务跟你没关系
- 空闲很久的 `done` 会话会衰减成 idle（默认 3 分钟），不长期占着宠物

实测：10 个会话里 4 个是后台的。

## 什么时候重算

| 事件 | 动作 |
|---|---|
| `sessions.changed` | 重新 `sessions.list` → 重算状态 |
| `session.message` | 检查 `unread` / `permissionModePending` |
| `session.tool` | 更新「正在跑什么」的副标题 |
| `chat`（含 `chat.inject`） | 同上 |
| 旋钮长按 | 强制刷新一次 |

## 字段会变怎么办

gateway 是活跃项目，字段可能增删改。三条对策：

1. **未知字段一律忽略**，不认识就不参与判定，不崩
2. **判定只用最小集**：`status` / `hasActiveRun` / `unread` / `permissionModePending` / `isBackground`。这几个够撑起全部状态
3. **映射表放在 JSON 里**（见下），上游改字段时改配置不改代码

## 映射配置

判定规则放在 petd 的 `data/state_rules.json`，长这样：

```json
{
  "version": 1,
  "priority": ["waiting", "error", "working", "done", "idle"],
  "stability": {
    "idleAfterMs": 3000,
    "idleGraceMs": 30000,
    "eventDebounceMs": 200,
    "doneDecayMs": 180000
  },
  "rules": {
    "error":   { "all": [{ "status": "error" }] },
    "waiting": { "any": [{ "permissionModePending": true }, { "unread": true }] },
    "working": { "all": [{ "status": "running" }, { "hasActiveRun": true }] },
    "done":    { "all": [{ "status": "done" }] },
    "idle":    { "none": [{ "status": "running", "hasActiveRun": true }] }
  },
  "exclude": { "isBackground": true }
}
```

`idle` 仍保留 `none` 排除规则作为**第二道**防线 —— 第一道是 `stability` 的稳态窗。两者都要有。

新增一个中间状态（比如 `thinking`）只要加一条规则 + 一个美术目录。
