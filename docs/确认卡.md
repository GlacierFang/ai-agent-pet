# 确认卡 —— 把选择题放到屏上

> 🟢 已实现（服务端功能，不刷固件）。开发中 AI 遇到岔路需要人拍板时，
> 把这道题推到屏上，用户转旋钮选一下，答案自动回到发起方会话。

## 一句话

一张卡 = 一个问题 + 2~4 个选项。旋转切选项，短按确认，长按取消。
答完的答案以一条消息回到**发起这张卡的会话** —— AI 下一次读上下文
就知道用户选了哪项，不用人再打字说一遍。

## 旋钮语义

| 手势 | 作用 |
|---|---|
| 旋转 | 切换选项 |
| 短按 | 确认当前项 |
| 长按 | 取消这张卡 |

确认卡在场时旋钮归它，不走 `gestures.json` 的动作表 ——
它是临时覆盖层，答完就还回去。`rot_press`（按住+转）在确认卡上不做事。

## 多会话并发

屏上一次只答一张，但队列里可以有多张。规则：

| 场景 | 处理 |
|---|---|
| 多个会话各有卡 | 队列上限 3 张；屏上只显示当前该答的那张 |
| 同一会话连问 | 新问题顶掉自己的旧卡，旧卡状态 `superseded` 并单独回程 |
| 显示哪张 | 优先显示**焦点会话**的卡（跟着宠物反映的会话走）；焦点没卡才回退到队首 |
| 超时 | 默认 5 分钟未答 → `expired`，回程告诉发起方按默认选项继续 |
| 回程隔离 | 每张卡自带 `sessionKey`，答案注回发起它的那一个会话 |

## 状态机

`pending` → `answered` / `cancelled` / `expired` / `superseded`

## 接口

全部受后台口令保护，路径在 `/admin/api/confirm*`。

```bash
# 发起
curl -s -b $COOKIE -X POST http://127.0.0.1:18860/admin/api/confirm \
  -H 'Content-Type: application/json' \
  -d '{"question":"用哪套渲染管线","options":["加分支","重写"],"sessionKey":"agent:main:..."}'

# 查看当前卡 + 队列
curl -s -b $COOKIE http://127.0.0.1:18860/admin/api/confirm

# 指定回答某张卡（屏上答不了的那张）
curl -s -b $COOKIE -X POST http://127.0.0.1:18860/admin/api/confirm/answer \
  -H 'Content-Type: application/json' -d '{"id":"<cardId>","answer":"加分支"}'

# 取消某张卡
curl -s -b $COOKIE -X POST http://127.0.0.1:18860/admin/api/confirm/cancel \
  -H 'Content-Type: application/json' -d '{"id":"<cardId>"}'
```

`sessionKey` 建议显式填发起方会话 —— 不填就回给宠物当前反映的会话，
多会话并行时可能回错地方。

`source` 可选，显示在屏上顶栏 —— 多会话时用户要知道是谁在问他。

## 回程

答案以一条**用户消息**回到发起方会话 —— 它会唤醒新一轮 agent run：

```
[确认卡 3f2a1b9c] 用哪套渲染管线
用户选择了：**加分支**
```

卡 id 在标题里 —— 多张卡并行时，能知道回的是哪一张。

四种结束态各回一句，语义不同：

| 结束态 | 回程 |
|---|---|
| 选了某项 | `用户选择了：**<选项>**` |
| 长按取消 | `用户主动取消了这个问题，不必重复询问。` |
| 超时 | `无人应答，这张卡已超时，按默认选项继续。` |
| 被同会话新问题取代 | `这个问题已被另一个新问题取代。` |

底层是 gateway 的 `chat.send`（write-scoped）。`petd` 的 gateway scope 已从
`operator.read` 调整为 `operator.read + operator.write` —— 只读 scope 会被拒。

## 兜底

答案同时落盘到 `petd/data/confirm_answers.jsonl`。
网关断了、回程失败，答案也不会丢 —— 网关恢复后重发。

## 边界

- 只支持选项，不支持自由文本输入
- 确认卡只回答问题，**不直接触发破坏性动作**
- 设备在游戏里时不弹卡（设备本地接管了屏幕），卡留在队列里
- 纯服务端功能：不刷固件、不改设备协议
- 问题 ≤60 字，选项 ≤24 字、≤4 个 —— 屏只有 240×320

## 什么时候该用

看三条：

1. **装不装得下** —— 能不能用 2~4 个短选项说完
2. **是不是必须回答才能往下走** —— 阻塞点才值得占住一块屏
3. **人此刻在不在设备旁边** —— 在旁边就推卡，不在旁边就在聊天里问

主题不是判据：开发决策照样能推，只要选项装得下、而且卡住了后面的活。
破坏性操作不推 —— 确认卡只回答问题，不直接执行动作。
