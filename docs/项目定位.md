# 项目定位

## 私有化部署

这是一个**私有化部署**项目：每位使用者在自己机器上跑一个 petd，服务一只自己的宠物。

**理由（从硬件倒推）**：

| 事实 | 推论 |
|---|---|
| 一台 ESP32-S3 + 一块屏 + 一个旋钮，物理上只服务一个人 | 硬件无法共享 → 不存在「多用户共用一个服务」 |
| petd 订阅的是使用者自己的 gateway，看的是他自己的会话状态 | 别人的会话对他毫无意义 |
| 设备通过 mDNS 在局域网找到 petd | 天然单机，无需云端设备注册 |

**所以这些一律不做**：账号体系 · 注册登录 · 邀请码 · 模式广场 · 设备云端绑定 · 多租户隔离 · 分享与社交。

**开源的意义**是「让别人的宠物也长这样」，不是「让一堆人共享一个服务」。

### 与多租户 SaaS 的差异

| | 多租户 SaaS | 私有化部署（本项目） |
|---|---|---|
| 账号体系 | 注册 / 登录 / 邀请码 | 无 |
| 设备绑定 | 云端绑定 | 无（mDNS 局域网自发现） |
| 模式广场 | 公开展示 | 无 |
| 配置存储 | 云数据库 | 本地 JSON |
| 固件升级 | 官方服务器统一下发 | 后台点一下就 OTA（≥ 0.5.7）；首次仍要 USB 整片刷 |
| 后台页 | 产品 Web 界面 | 部署者的管理控制台（见 [后台控制台](后台控制台.md)） |
| 文档重心 | SaaS 使用指南 | 私有化部署手册（见 [部署手册](部署手册.md)） |

### 代价

文档责任变重 —— 每个使用者都得自己动手接线、编译、部署。**这是私有化定位的必然结果。** 第一读者是「愿意在自己桌上装一只宠物的人」。

## 仓库结构

Python 服务端和 ESP-IDF 固件放在同一个仓库。

```
ai-agent-pet/
├── petd/                # Python 包
│   ├── __main__.py      # 命令行入口
│   ├── gateway.py       # 握手与 scope 逻辑
│   ├── state.py         # 会话 → 宠物状态
│   ├── render.py        # Pillow 渲染成 JPEG
│   ├── screen.py        # 两层互斥的屏仲裁
│   ├── gestures.py      # 旋钮手势分派
│   ├── features/        # 内容卡：会话 / 通知 / 最近完成 / 时间 / 主机 / 天气 / 相册 / 功德 / 骰子
│   ├── static/admin/    # 后台控制台（单页，无构建链）
│   └── data/            # 随版本走的默认值 + 本机配置（后者不进仓库）
├── firmware/            # ESP-IDF
│   ├── sdkconfig.defaults    # 可复现构建的关键
│   ├── partitions.csv
│   └── main/             # 显示 / WebSocket / 旋钮 / SoftAP 配网
├── skins/               # 内置素材
├── tests/
├── deploy/              # systemd 单元与环境变量样例
├── docs/
├── LICENSE  README.md
├── CONTRIBUTING.md  SECURITY.md  CHANGELOG.md
└── THIRD_PARTY_NOTICES.md
```

## 合规判断

> 以下是工程判断，不是法律意见。要卖硬件请找专业人士确认。

| 项 | 判断 |
|---|---|
| DevKitC 用 ESP32-S3-WROOM 模组 | 模组本身带 FCC/CE/SRRC 认证，基于已认证模组的成品**可能**沿用认证 —— **需核实** |
| 纯开源分发 | 不触发 CE 认证义务 |
| 卖预组装成品 | 要 Responsible Party（欧盟）/ FCC ID |
| 无线频段 | ESP32-S3 只支持 2.4GHz，无频段风险 |
| 电池 | 无电池 → 不涉及 UN38.3 运输认证 |
