## 定位：私有化部署

🟢 **2026-11-03 确定：这是私有化部署项目，不是多租户 SaaS。**

**理由（从硬件倒推）**：

| 事实 | 推论 |
|---|---|
| 一台 ESP32-S3 + 一块屏 + 一个旋钮，物理上只服务一个人 | 硬件无法共享 → 不存在「多用户共用一个服务」 |
| petd 订阅的是**使用者自己**的 gateway，看的是**他自己的**会话状态 | 别人的会话对他毫无意义 |
| 设备通过 mDNS 在局域网找到 petd | 天然单机，无需云端设备注册 |

**所以这些一律不做**：账号体系 · 注册登录 · 邀请码 · 模式广场 · 设备云端绑定 · 多租户隔离 · 分享与社交。

**开源的意义**是「让别人的宠物也长这样」，不是「让一堆人共享一个服务」。

### 由此决定的差异

| | 多租户 SaaS | 私有化部署（本项目） |
|---|---|---|
| 账号体系 | 注册 / 登录 / 邀请码 | **无** |
| 设备绑定 | 云端绑定 | **无**（mDNS 局域网自发现） |
| 模式广场 | 公开展示 | **无** |
| 配置存储 | 云数据库 | **本地 YAML / JSON** |
| OTA 分发 | 官方服务器统一发 | **各人自己的 GitHub Release** |
| 后台页 | 产品 Web 界面 | **部署者的管理控制台**（见 [后台控制台](后台控制台.md)） |
| 文档重心 | SaaS 使用指南 | **私有化部署手册**（见 [部署手册](部署手册.md)） |

### 代价

文档责任变重 —— 每个使用者都得自己动手接线、编译、部署。**这是私有化定位的必然结果，不是可以绕过的负担。** 第一读者是「愿意在自己桌上装一只宠物的人」。

## 合规判断

> 🟡 以下是判断，不是法律意见。真要卖硬件请找专业人士确认。

| 项 | 判断 |
|---|---|
| DevKitC 用 ESP32-S3-WROOM 模组 | 模组本身带 FCC/CE/SRRC 认证，基于已认证模组的成品**可能**沿用认证 —— **需核实** |
| 纯开源分发 | 不触发 CE 认证义务 |
| 卖预组装成品 | 要 Responsible Party（欧盟）/ FCC ID |
| 无线频段 | ESP32-S3 只支持 2.4GHz，无频段风险 |
| 电池 | 无电池 → 不涉及 UN38.3 运输认证 |
| 项目名带 `openclaw-` 前缀 | 可能与上游商标政策冲突 —— 发布前查一下 |

## 发布前必须解决的

1. **LICENSE**（建议 Apache-2.0 —— 比 MIT 多一层专利授权，对硬件+软件混合项目更稳）
2. **默认角色程序化生成** —— 决定「clone 下来能不能直接用」和「能不能商用分发」
3. **README 首屏 GIF** —— 「agent 干活时它在旁边打工人、等你审批时举牌子」。**这段是整个项目最值钱的素材**，但要等宠物真能跑起来
4. **维护者承诺** —— README 写明谁维护、多久看一次 issue。这不是形式，是别人敢不敢用的前提
