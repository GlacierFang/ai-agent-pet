# 旋钮（KY-040）

> 🟢 已实现。手势阈值与语义映射都在服务端，改配置不刷固件。
>
> 📌 模块丝印是 `GND / + / SW / DT / CLK` —— 第五针是 **CLK**（不是 ENC），
> 接线见 [硬件指南](硬件指南.md)。

## 核心原则

**旋钮的语义表在服务端，设备只报原始事件。**

固件里没有「短按=切页」这种判断 —— 它只知道「SW 按了 1200ms」「ENC 转了 +3 步」。所以：

- 改手势含义 = 改 petd 侧一个 JSON，**不刷固件、不重启服务**
- 新增手势 = 加一条绑定，同样不动固件
- 固件只负责三件事：把编码器脉冲累加成步数、量出 SW 按住毫秒数、区分旋转时 SW 是否按着

## 手势预算（KY-040 实际能给的 4 类）

| 手势 | 设备如何判定 | 上报 | 默认语义 |
|---|---|---|---|
| 旋转 | ENC 脉冲累加 | `{"t":"input","ev":"rot","dir":1,"steps":3}` | 翻到下一张卡 |
| 短按 | SW 按下并松开，`ms < 600` | `{"t":"input","ev":"press","btn":"sw","ms":120}` | 摇骰子 |
| 长按 | SW 按住 `ms ≥ 600` | `{"t":"input","ev":"press","btn":"sw","ms":1200}` | 立刻刷新状态 |
| 按住+旋转 | SW 按下期间 ENC 变化 | `{"t":"input","ev":"rot_press","dir":-1,"steps":2}` | 换信息密度档位 |

**长按阈值 600ms 定在服务端** —— 设备只报 `ms` 原始值，petd 按阈值分派短/长，改阈值不刷固件。

**一个旋转事件 = 翻一张卡** —— 设备把 30ms 窗口内的编码器脉冲聚合成一个 `rot` 事件（带步数），petd 收到就翻一张卡。
注意：`gestures.json` 里的 `stepsPerAction` 目前**没有任何代码读取**（后台页面会显示它），实际生效的是「一个齿 = 一张卡」。

🟢 **已在实机验证**（fw-v0.4.7 + 修好 `devices.ack` 的服务端）：旋转翻卡、短按弹骰子、长按刷新、按住旋转切密度，四类手势端到端可用。
旋钮事件要能到服务端，服务端也得是修好的版本 —— 旧服务端收到设备第一帧 `frameAck` 就会掐断连接，旋钮事件全丢，见 [故障排查](故障排查.md)。

> KY-040 的 tact switch 与编码器是**两路独立信号**，所以「按住+旋转」天然可实现，不需要特殊硬件。

🟢 **实机手感正常** —— 旋转方向正确、每圈步数合理，一个齿翻一张卡。
（KY-040 常见规格是 20 PPR，但实际拿到的件可能不同 —— 手感以实机为准，别按规格推算。）

🟢 **5ms 消抖窗口够用** —— 实机上廉价件的脉冲抖动没有造成误报。

## 语义表

`petd/data/gestures.json`：

```json
{
  "version": 3,
  "longPressMs": 600,
  "stepsPerAction": 4,
  "actions": {
    "rot":        "card.next",
    "rot_press":  "density.cycle",
    "press_long": "state.refresh",
    "press_short": "dice.roll"
  }
}
```

**一张表管所有屏** —— 屏上只有宠物形象和内容卡两层，没有多页面，所以表里不分模式。
`press_short` 留空表示这个手势不分配任何动作。

**`press_short` 现在是「摇骰子」** —— 骰子不是宠物状态，是一次性覆盖层：
按一下开，再按一下收，宠物忙或睡着时不弹。它跟「按住+旋转换密度」不冲突：
一个按，一个按住转，两路信号本来就分开。

**表只做「每个手势对应哪个 action」的映射，与 handler 分离** —— 换 handler 不动表。

新增动作：在 petd 的 handler 表里注册一个函数，在 `gestures.json` 里加一行映射。两步都不用碰固件。


## 屏上现在有什么

屏上没有「页面」了 —— 只有宠物形象和 feature 卡片，整屏互斥。

| 状态 | 屏上 | 旋钮在这里干什么 |
|---|---|---|
| OpenClaw 在干活 | 宠物形象（working / waiting / error） | 没空翻卡 —— 旋钮不响应 |
| 活刚干完 | 宠物形象，留几秒 | 同上 |
| 宠物没事干 | feature 卡片轮播 | 旋转 = 翻到下一张卡，短按 = 摇骰子 |
| 骰子开着 | 整屏骰子 | 再按一下收起；来活了自动收起 |
| 夜间时段 | 睡觉 | 同上（短按也不弹骰子 —— 不吵醒它） |

按住 + 旋转 = 信息密度循环，长按 = 刷新会话状态。

手势表不分页面 —— 一张表管所有。语义表在 `petd/data/gestures.json`，
改配置不刷固件。

## 关键实现：文字全在 Pi 侧渲染，设备零字体

设备端不放任何中文字库（Flash 装不下、渲染也慢）。所有文字由 petd 用 Pillow 渲染进 JPEG。

### 长列表怎么办：页级翻页，不用像素级滚动

- petd 把长列表切成若干页，每页一张 240×320 的完整 JPEG
- 进入该页时**一次性预推**这些帧；设备把 JPEG 字节存 PSRAM
- 旋钮翻页 = 设备换一张已缓存的 JPEG 解码上屏（TJpgDec 流式），**零网络往返**
- 页数太多时（>10 页）服务端只推「当前页 ±2 页」，滚到边缘再补 —— 边界处有网络延迟，可接受

**🟢 列表页 JPEG 体积已用 Pillow 实测**（240×320，q85，4:2:0，Noto Sans CJK）：

| 一页内容 | 体积 |
|---|---|
| 2 条会话 | **8.4KB** |
| 5 条会话 | **16.4KB** |
| 8 条会话 | **22.7KB** |

按最坏 5 条会话 16.4KB 算，预推 ±2 页（5 页）约 **82KB** —— PSRAM 8MB 和 Wi-Fi 带宽都毫无压力。

**上屏耗时**（🟢 实机确认）：

- TJpgDec 解一帧 4:2:0：量级 15–30ms
- SPI 40MHz DMA 推整屏：240×320×2 = 153600 字节 = 1.229 Mbit ÷ 40MHz ≈ **31ms**
- 解码与传输可流水线并行 → **整屏约 35–45ms**

实机跑下来上屏基本上没有延时，与上面这个估算对得上。

即翻页动画理论上跑得动 20fps。

**加个滚动条指示**：列表页右缘渲染一条细长胶囊，标出「第几页 / 共几页」。页级翻页没有位置感，光靠转旋钮会不知道自己转到哪了 —— 胶囊条让位置一眼可见，成本几乎为零。

### 为什么不用「一张 240×1600 长图 + 设备像素级滚动」

（早期设想，已否。）

TJpgDec 是**顺序解码** —— 要显示第 900 行，就得把前面 56 个 MCU 行全解一遍，滚一下等几百毫秒。真做像素级滚动，设备得在 PSRAM 常驻一张解码后的帧缓冲（240×1600×2 = 768KB，N8R8 的 8MB 装得下），每次上屏还要把 16 行窗口从 PSRAM 拷进 SRAM 再走 SPI DMA（PSRAM 不能直接当 DMA 源）—— 多一套搬运机制。v1 不值得。

## 帧缓存与内存

设备只缓存**压缩后的 JPEG 字节**，不缓存解码后的像素：

- PSRAM 8MB 足够放几十页 JPEG
- 解码后的 240×320×2 = 150KB 像素缓冲**不常驻** → 沿用 TJpgDec 的 7.68KB line buffer 流式直刷
- PSRAM 只当「存储」不当「DMA 源」

## 还能玩出什么（v2+ 候选）

| 玩法 | 实现 | 依赖 |
|---|---|---|
| 长列表像素级滚动 | PSRAM 常驻帧缓冲 + 16 行窗口搬运 | v1 不做 |
| 一键「好 / 继续 / 取消」 | 短按映射到 `sessions.send` 预设回复 | 需 `operator.write` |
| 心情值 / 养成数值 | petd 侧持久化小状态机，转旋钮 = 互动 | 纯软件，成本最低 |
| 功德计数 + 骰子 | 已实现 —— 短按摇骰子，活干完功德 +1 | 🟢 已落地 |
| 专注计时 / 番茄钟 | petd 计时，长按暂停 | 纯软件 |
| 待办、日程 | 走 feature 机制新增模块 | 纯软件 |
| 旋钮调音量 | — | ❌ 本板无音频硬件 |
| 旋钮调背光亮度 | — | ❌ BL 不接 GPIO，做不了 PWM 调光 |
