## 0.5.4

这一版的主线是**设备端固件自更新**：以后升级不用再插 USB，由人在后台点一下，设备自己换分区重启。

### 怎么用 OTA

**升级由人决定。** 设备**不会**自己升级 —— 后台只显示「当前 0.5.2，可用 0.5.4」，等人点了才动手。这是本项目的硬规则：没有账号体系、没有自动推送、没有人不在场时的动作。

一次完整升级是这样走的：

1. 后台登记固件 —— 上传 `petd.bin` 文件，或者填一个 URL 让 petd 自己去取（私有化部署多半连不上 GitHub Release，内网 NAS 也行）。petd 自动算 sha256 并写进版本登记表
2. 设备连上来 —— hello 报文里带上自己的 `fw` 版本号，后台列表显示「当前版本 / 可用版本」
3. **人在后台点「升级」** —— petd 开始分片下发：`otaStart` → 反复「一片预告 + 一片本体」→ 最后 `otaFinish`
4. 设备校验并切换 —— 校验 sha256 通过才标记分区有效，然后切换启动分区、重启
5. 新固件连上来报新版本 —— 后台显示升级成功

分片大小 16KB。

### 安全边界

- **写的是另一个分区。** OTA 写进 `ota_0` / `ota_1`，不覆盖当前正在跑的那个分区。写到一半断电 → 那个分区无效，bootloader 照样跑旧固件。
- **校验由 IDF 完成。** app 镜像自带 app descriptor，`esp_ota_end()` 会自己算一遍 sha256，对不上直接失败，那个分区不会被标记为有效。设备上不用再算一遍。
- **跑不起来不会变砖。** 开了 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE`（bootloader 的防砖机制，不是回滚功能）：新固件起来后处于「待验证」状态，连上 petd 才确认有效；连不上就一直待验证，超时 bootloader 自动退回旧分区。
- **升级中屏上不黑屏。** 宠物整屏显示状态，不做动画 —— 升级期下载和渲染抢内存。

### ⚠️ 这一次仍要整片刷

**这一版改了 bootloader**（开了 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y`）。bootloader 变了，老设备上根本没有这个防砖能力，所以第一次上 0.5.4 必须走 USB 整片刷。

**刷完之后，0.5.5 及以后就能纯 OTA 了。**

整片刷参数跟之前一样：

| 项 | 值 |
|---|---|
| 地址 | `0x0` |
| SPI SPEED | `80MHz` |
| SPI MODE | `DIO` |
| ERASE | **不按** |

不按 ERASE 是为了保住 NVS 里已存的 Wi-Fi 配网信息。

### 资产说明

| 文件 | 用途 |
|---|---|
| `merged-binary.bin` | **整片镜像**，含 bootloader + 分区表 + app。刷这个（地址 `0x0`） |
| `petd.bin` | **app 分区镜像**。这才是 OTA 能用的文件 |
| `uf2.bin` | 给支持 UF2 的设备用 |
| `flash_args` / `flasher_args.json` | esptool / idf.py flash 的参数 |

**`merged-binary.bin` 绝不能当 OTA 的 app 镜像登记** —— 它是从 `0x0` 起的整片布局，OTA 只写 app 分区。登记错了一次就是砖。

### 顺带带上的

- **贪吃蛇修复** —— 转向 90°、速度降到 3 格/秒、碰撞框跟画面对齐。
- **逐包推送留间隔** —— 设备收包的队列只有 2 深，连续推送时挤不进去的会被丢掉，
  而设备留着旧包、服务端看不出异常。现在两个包之间留 0.5 秒。
