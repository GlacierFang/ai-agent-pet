# 0.5.9

**修纯 OTA 下发中断** —— 真机第一次跑 OTA 就撞上的问题。

## 症状

后台点「升级」，下到一半断：

```
OTA 下发中断在第 16 片
```

**每次断的片数都不一样** —— 实测 16 / 20 / 26 / 29 片。断线后设备自己重连，
服务端重发游戏包和 hello，握手正常，屏上也不死循环了 —— 就是固件传不下去。

第二次尝试时进度从 **41%** 接着走（不是从 0%）—— 说明设备没重启，
RAM 状态还在，是 **WebSocket 连接断了**。

## 根因

三处叠加。

### 1. 服务端没有流控（主因）

服务端一口气把 1MB 固件在 **3.2 秒**里全灌过去（65 片，片间只 sleep 50ms）。
而设备端的 OTA 收包队列只有 **4 深**，写 flash 又慢（一片要擦扇区）。

队列一满，`xQueueSend` 就开始等 —— 而这个调用跑在 **WebSocket 收包任务里**。
等 2 秒等不到位置，整个 WS 收包任务就停摆，连接断掉。

### 2. 设备 WS 回调里做了 flash 操作

`ota_handle_start` 直接在 WS 回调里调 `esp_ota_begin`，
断线时还在回调里调 `esp_ota_abort`（**会擦 flash**）。
flash 操作跑在收包任务里 → 连接被拖慢甚至卡死。

### 3. 失败重试会把镜像写坏

设备端 `ota_handle_start` 看到「已经在下载」就直接 return false。
服务端从第 0 片重下，新片接在**旧片的偏移**上 —— 镜像静默损坏。

还有一条更狠的：`ota_fail()` 只把 `s_handle` 清零，**没调 `esp_ota_abort`**。
分区还开着，下次 `esp_ota_begin` 会返回 `ESP_ERR_INVALID_STATE` ——
**设备从此再也装不了固件，只能断电重启**。

## 改动

### 服务端

- **等设备确认再发下一片**。设备每写完一片回一条 `otaStatus`（带 `seq`），
  petd 等到这一片的确认才发下一片（超时 30 秒）。
- **确认必须 0..N 连续**。只看「最大 seq」不够 —— 上一轮迟到的确认会把中间
  的空缺填上，看起来像连续，镜像就写坏了。
- **轮次号**。`otaStart` 带 `round`，设备在 `otaStatus` 里回。对不上轮次的
  确认直接丢掉。
- **设备报 `ok:false` 立刻停手**，不再往设备推坏数据。
- **OTA 期间不推帧** —— 设备正忙着写 flash，屏上自己画进度。抢带宽只会让
  固件片更容易挤爆设备的收包队列。
- **设备卡在上一轮 OTA 时说清楚要怎么做**：0.5.9 起的固件能自己作废重来；
  更老的固件只能断电重启，服务端直接把这个说清楚，不让用户干等。

### 设备端

- **flash 操作全部挪出 WebSocket 回调**。回调只把字节收进缓冲，
  真正的写盘交给 `ota_task`。`ota_handle_start` 也变成「只排队」。
- **断线就作废这轮 OTA**。回调只**请求** abort（置标志），由 `ota_task` 去做 ——
  `esp_ota_abort` 要擦 flash，不能跑在收包任务里。
- **中途能重来**。`ota_handle_start` 发现「已经在下载」就作废上一轮、从头来，
  不再把新片接在旧片偏移上。
- **`ota_fail()` 会 abort 分区** —— 不 abort 的话设备从此装不了固件。
- **队列满就直接丢，绝不在回调里等**。丢掉这一片的后果是服务端等不到确认、
  超时退出 —— 干净失败，比把连接搞死好得多。
- **`esp_ota_end` 之后先存返回值再清 handle** —— 之后再拿它去 abort 就是
  拿废句柄擦 flash。

## 这次改了什么、没改什么

改的：**OTA 的下发节奏、确认语义、设备端 flash 操作的执行位置**。

没改的：OTA 协议的基本形状（`otaStart` / `otaChunk` / `otaFinish` /
`otaStatus` 四条消息）、分片大小（16KB）、写哪个分区、校验和切分区的逻辑。
`round` 是**可选**字段 —— 设备回 -1 表示没有，服务端也就当没有。

## 验证

- 新增 `tests/test_ota_flow_control.py`（12 条）：确认语义、连续性、轮次隔离、
  下发必须等确认、设备报错要停手、卡住时的门槛。
- 全量 503 passed，固件宿主测试 0 项失败。

**还没在真机上验证。** 服务端这半边改了就能立刻用（设备是 0.5.7 也能配合 ——
`round` 缺省就是没有），但设备端那半边要刷 0.5.9 才生效。

## 资产说明

| 文件 | 用途 |
|---|---|
| `petd.bin` | **app 分区镜像**。OTA 推这个 |
| `merged-binary.bin` | 整片镜像（含 bootloader + 分区表 + app）。地址 `0x0` |
| `uf2.bin` | 给支持 UF2 的设备用 |
| `flash_args` / `flasher_args.json` | esptool / idf.py flash 的参数 |

整片刷参数：地址 `0x0`、SPI SPEED `80MHz`、SPI MODE `DIO`、**不按 ERASE**（保住 NVS 里的 Wi-Fi 配网信息）。

> ⚠️ **`merged-binary.bin` 绝不能当 OTA 的 app 镜像登记** —— 它是从 `0x0` 起的整片布局，OTA 只写 app 分区。登记错了一次就是砖。
