## 0.5.8

**这一版是纯 OTA 的验证载体** —— 固件逻辑一个字没改，只有版本号从 `0.5.7` 变成 `0.5.8`。

### 为什么发这一版

项目到现在为止，**纯 OTA 一次都没在真机上跑通过**。0.5.5 当初也是同样的用法：
用一次版本号 bump 去验证 OTA 链路本身，把「固件逻辑对不对」和「OTA 通不通」
两件事分开。0.5.7 修好了握手，设备终于能连上后台了 —— 现在正好是验证 OTA 的时机。

### 这一版验证什么

1. 后台「固件」页登记 `petd.bin` → 设备端显示「可用 0.5.8」
2. 人点「升级」→ petd 分片下发（16KB 一片）→ 设备写进 `ota_0`/`ota_1` 的另一个分区
3. 校验 sha256 通过 → 切启动分区 → 重启
4. 重启后设备用 **0.5.8** 重新握手 —— 后台「设备接入」记录里的 `fw` 字段变了
第 4 步成功 = OTA 闭环成立。

### 不做自动升级

设备**不会**自己升级。它没有下载器，也没有「有新版本就升」的逻辑。
注册、下发、点「升级」——三个动作都在后台，由人点。

### 资产说明

| 文件 | 用途 |
|---|---|
| `petd.bin` | **app 分区镜像**。OTA 推这个 |
| `merged-binary.bin` | 整片镜像（含 bootloader + 分区表 + app）。地址 `0x0` |
| `uf2.bin` | 给支持 UF2 的设备用 |
| `flash_args` / `flasher_args.json` | esptool / idf.py flash 的参数 |

整片刷参数：地址 `0x0`、SPI SPEED `80MHz`、SPI MODE `DIO`、**不按 ERASE**（保住 NVS 里的 Wi-Fi 配网信息）。

> ⚠️ **`merged-binary.bin` 绝不能当 OTA 的 app 镜像登记** —— 它是从 `0x0` 起的整片布局，OTA 只写 app 分区。登记错了一次就是砖。
