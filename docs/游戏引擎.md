# 游戏引擎（设备端小游戏）

> 已实现：引擎代码在 `firmware/main/game/`，游戏包在 `petd/packs/`（骰子、贪吃蛇）。
> 文中数字分两类：**实测**（来自现有代码与实机）、**估算**（设计推算，实现时要重新核）。

## 目标

设备自带一组小游戏，**断网也能玩**。

游戏跑在设备固件里，不依赖 petd、不依赖 OpenClaw、不依赖 LLM、不依赖互联网。
petd 在，只负责把游戏包推给设备；petd 不在，设备照玩。

## 为什么游戏必须在设备上，不在服务端

服务端渲染是「整帧 JPEG → 设备解码 → SPI 推全屏」（实测见 `docs/固件构建.md`）：

| 路径 | 每帧字节 | 26MHz SPI 耗时 | 帧率 |
|---|---|---|---|
| 整帧 JPEG（240×320×2） | 153,600 | ≈47ms（+解码 2ms） | **≈20fps** |
| 局部刷新（挡板+球+一格砖 ≈1.1KB） | ~1,100 | ≈0.3ms | 60fps 无压力 |

服务端推帧的活动帧率是 10fps（`petd/config.py` 的 `frame.activeFps`）。球每帧要动的游戏走这条路，
球会一顿一顿还叠网络往返 —— **消砖块在服务端做不了**。

反过来，**不需要连续动画的玩具可以留在服务端**（现在的骰子就是这样：服务端算好一帧覆盖层推下去）。
但本设计把骰子也搬进设备，让整个游戏体系只有一套。

## 硬约束

这些是设计前提，不是可选项：

| 约束 | 原因 |
|---|---|
| **不做 OTA** | 固件只能 USB 烧录（`docs/部署手册.md`） |
| **不做游戏商店 / 账号 / 评分 / 排行榜** | 我们是开发者，不是发行平台。仓库给参考实现，用户自己开发 |
| **不做历史记录** | 小游戏就是小游戏：开始 → 玩 → 结束 → 回菜单，不留痕 |
| **游戏是数据包，不是代码** | 加游戏不能刷固件。加一个游戏 = 加一个 pack 文件 |
| **我们只维护自己那几个** | 消砖块、贪吃蛇、钓鱼、骰子。俄罗斯方块往后放，不做 |

**「不做 OTA」和「游戏是数据包」是同一个决定的两面** —— 不能靠刷新固件来加游戏，
游戏就必须以数据形式存在。这两条互为因果，不是两个独立需求。

## 交互

| 手势 | 屏幕状态 | 行为 |
|---|---|---|
| 短按 | 宠物 | 打开游戏菜单 |
| 短按 | 菜单 | 确认，开始游戏 |
| 旋转 | 菜单 | 上下选择 |
| 旋转 | 游戏内 | 游戏自己定义（挡板移动 / 转向 / 瞄准…） |
| 短按 | 游戏内 | 游戏自己定义（发球 / 放下 / 确认） |
| 长按 | 任意 | 退出游戏 → 回菜单 |

**短按打开游戏菜单** —— 菜单里是游戏列表（骰子、贪吃蛇），菜单本身画在设备上（`firmware/main/game/game_menu.c`）。

**长按退出在设备侧判定。** 设备已经能从 `welcome` 里拿到服务端的 `longPressMs`
（`firmware/main/ws_client.c` 已解析这个字段），所以设备自己分得清短按/长按，
不需要新增协议字段。

## 架构

固件里的游戏部分分三层：

```
┌─────────────────────────────────────────┐
│  Runtime     固定步长 60Hz 循环 · 模式状态机 · 输入分发 │
├─────────────────────────────────────────┤
│  Components  组件库：空间/形状/碰撞/网格/行为/渲染     │
├─────────────────────────────────────────┤
│  Pack loader 读 SPIFFS → 解析 JSON → 校验能力 → 建场景   │
└─────────────────────────────────────────┘
```

**关键约束：引擎里不许出现游戏语义。** 没有 `brick`、没有 `paddle`、没有 `snake` ——
只有 rect / circle / grid / trail / gauge 这类通用组件。
新游戏靠**组合**已有组件，不靠加 if 分支。这是「前期兼容」的根本。

## 能力表（引擎原语）

这张表就是「引擎能承载什么」的答案。**写游戏只能用表里的东西**；
表里没有的，要么改需求，要么给引擎加一个新组件（那是一次固件改动）。

### 空间

| 能力 | 参数 | 说明 |
|---|---|---|
| `pos` | x, y, anchor | 位置与锚点（center / top-left） |
| `vel` | vx, vy | 速度，每逻辑步积分 |
| `accel` | ax, ay | 重力 / 阻尼 |
| `bounds` | 左上右下, bounce | 撞屏边反弹 |

### 形状

| 能力 | 参数 | 说明 |
|---|---|---|
| `shape.rect` | w, h | 轴对齐矩形 |
| `shape.circle` | r | 圆 |
| `shape.sprite` | 资源名 | 位图，来源：pack 自带或固件内置 |

> **暂不支持精灵旋转。** ST7789 没有硬件旋转，软件转 240×320 全屏太贵。
> 俄罗斯方块那种「方块转 90°」是网格内的格子重排，不是精灵旋转 —— 所以不受影响。

### 碰撞

| 能力 | 参数 | 说明 |
|---|---|---|
| `collider.solid` | restitution, spin | 实体碰撞，有响应（反弹 / 摩擦） |
| `collider.trigger` | — | 只发事件，不响应（吃到砖块、咬钩） |
| 检测组合 | 圆↔圆、圆↔矩形、矩形↔矩形、点↔矩形 | 引擎内置 |

### 网格

| 能力 | 参数 | 说明 |
|---|---|---|
| `grid` | cols, rows, cell, origin, pattern, colors | 砖块阵、扫雷盘面 |
| `grid.on_hit` | 效果 | 命中格子后的效果（消除格子） |
| `grid.solid_at` | 查询 | 某格是否被占（贪吃蛇撞自己） |

### 行为

| 能力 | 参数 | 说明 |
|---|---|---|
| `trail` | len | 记录最近 N 个位置（贪吃蛇身体） |
| `timer` | interval, once | 周期 / 延时触发事件 |
| `random_move` | speed | 随机漫游（鱼） |
| `gauge` | value, target, tolerance | 一个 0..1 的量 + 目标区（钓鱼张力） |
| `progress` | value | 进度（拉竿距离） |

### 渲染

| 能力 | 参数 | 说明 |
|---|---|---|
| `color` | RGB | 填充色 |
| `alpha` | 0..255 | 半透明混合（引擎自己混合） |
| `text` | 字符串, 字体 | ASCII 用固件内置 5×7；中文用 pack 自带点阵 |
| `z` | 整数 | 绘制顺序 |

### 事件

`hit`（实体碰撞）、`enter` / `exit`（进入离开区域）、`tick`（每步）、
`press` / `rotate`（输入）、`destroyed`、`empty`、`state_change`

### 效果

`set_vel` / `add_vel` / `set_pos` / `add_score` / `destroy` / `spawn` /
`set_state` / `emit` / `random` / `win` / `lose`

**没有音效。** 这块板没有蜂鸣器，背光也没 PWM（`firmware/main/display.c` 注释：
「背光 BL 直接接 3.3V，不受控」）—— 反馈全靠画面。

## Pack 格式

一个 JSON 文件就是一个游戏。格式定死，以后加游戏照着填。

```json
{
  "id": "brickout",
  "version": 1,
  "title": "消砖块",
  "hint": "旋转移动挡板 · 按下发球 · 长按退出",
  "requires": ["rect", "circle", "collide_circle_rect", "vel", "bounds", "grid"],

  "input": {
    "rot":        { "intent": "move_x", "entity": "paddle", "scale": 6.0 },
    "press":      { "intent": "fire",    "entity": "ball" },
    "rot_press":  { "intent": "move_x",  "entity": "paddle", "scale": 14.0 },
    "press_long": { "intent": "quit" }
  },

  "entities": [
    { "id": "paddle", "shape": "rect", "w": 44, "h": 8,
      "pos": [120, 292], "anchor": "center", "color": "#E8E8F0",
      "collider": { "kind": "solid", "restitution": 1.0, "spin": 0.32 } },

    { "id": "ball", "shape": "circle", "r": 4,
      "pos": [120, 260], "vel": [1.7, -2.3], "speed": 3.6,
      "color": "#E8B000",
      "collider": { "kind": "solid", "restitution": 1.0 },
      "trigger": ["bricks"] }
  ],

  "grid": {
    "id": "bricks", "cols": 9, "rows": 5,
    "origin": [12, 44], "cell": [24, 12], "gap": [2, 2],
    "pattern": ["111111111","111111111","111111111","111111111","111111111"],
    "colors": { "1": "#C80000" },
    "on_hit":  { "effect": "destroy_cell" },
    "on_empty": { "intent": "win" }
  },

  "rules": [
    { "on": "hit", "target": "bricks", "effects": [
        { "effect": "add_score", "value": 10 },
        { "effect": "set_vel", "entity": "ball", "mul": [1.0, -1.0] }
    ] },
    { "on": "out_of_bounds", "target": "ball", "effects": [
        { "effect": "lose" }
    ] }
  ]
}
```

### 中文怎么办

pack 自己带字模。`glyphs` 字段把用到的汉字映射成 12×12 位图（base64）。
仓库里放一个生成脚本 `tools/gen_pack_glyphs.py` —— 读 pack、找出所有汉字、
用系统 CJK 字体渲染成 12×12 点阵、写回 pack。
这样**加游戏不需要重刷固件就能显示中文**，也不用多开一条资源下发通道。

## 能力协商

pack 的 `requires` 声明它要用哪些能力。固件缺能力时：

- **拒绝加载，屏上显示「该游戏需要更新固件」**
- 不许黑屏、不许乱跑

这是兼容性的关键 —— **失败要可读**。

pack 的 `version` 与固件支持的 pack 版本比较，不匹配同样走可读失败。

## 协议新增

协议**保持 v1**，全部是向后兼容的增量：

| 方向 | type | 载荷 |
|---|---|---|
| petd → 设备 | `pack`（新） | `{"type":"pack","id":"brickout","version":1,"data":{...}}` |
| 设备 → petd | `packAck`（新） | `{"type":"packAck","id":"brickout","ok":true}` |

其余靠**已有消息加字段**，不新增消息类型：

| 消息 | 新增字段 | 用途 |
|---|---|---|
| `hello`（设备 → petd） | `packs` | 设备报告 SPIFFS 里已有哪些包。petd 对比后只补缺的 |
| `status`（设备 → petd） | `mode` | `idle` / `menu` / `playing`。petd 据此停推帧 |

`hello.packs` 让整个下发流程**自愈**：每次重连，设备报自己有什么，petd 补差额。
不需要单独的「我要包」消息。

老固件不认识 `pack` 消息会直接忽略（现有的消息分派只认已知 type），
所以**现有设备不受影响**，宠物照常工作。

```

  game_glyph.c      pack 字模解码与绘制

  manifest.json     id / 标题 / 顺序
  brickout.json
  snake.json
  fishing.json
  dice.json
```

## 固件改动清单

**新增**：上面 `firmware/main/game/` 全部文件；`game_pack.c` 里挂载 SPIFFS。

**修改**：

| 文件 | 改什么 |
|---|---|
| `firmware/main/CMakeLists.txt` | 加 game 源文件；REQUIRES 加 `spiffs` |
| `firmware/main/app_main.c` | screen_task 分成「宠物屏」和「游戏屏」两条路；knob_task 在游戏模式下把事件交给引擎而不是转给服务端 |
| `firmware/main/ws_client.c` | 二进制帧到达时，若设备在游戏模式则**不画**（否则会覆盖游戏画面） |
| `firmware/main/display.c` | 加一个内部 SRAM 的 DMA scratch（**SPI DMA 源不能是 PSRAM**） |

**完全不动**：显示驱动核心、旋钮驱动（它只报原始量，正好）、WS 框架、配网、宠物渲染管线。

**空间核算**（实测）：

| 项 | 数字 |
|---|---|
| `fw-v0.4.7` petd.bin | 949 KB |
| app 分区（factory/ota_0/ota_1） | 各 2 MB → **约 1 MB 余量** |
| `storage` 分区 | **1 MB SPIFFS，已划好，固件从未挂载过** |
| 全屏画布（PSRAM 240×320×2） | 150 KB（PSRAM 8MB，够） |
| DMA scratch（内部 SRAM） | 几 KB |

**内存注意**：画布可以放 PSRAM，但**每次推给屏的源缓冲必须在内部 SRAM**
（SPI DMA 不能从 PSRAM 取源）。球 8×8、挡板 44×8 分别只要 128 / 704 字节。

## 中文点阵

设备内置 5×7 ASCII（`firmware/main/ascii_font.h`）。中文用 12×12 位图，
由 pack 自带、仓库脚本生成。

**12×12 的取舍**：比 16×16 小一圈，一行能放 20 个字（240px）。生成脚本 `tools/gen_pack_glyphs.py` 用 PIL 渲染 12px 中文字体，
像素灰度 ≥96 记为一点（`GLYPH_W = GLYPH_H = 12`，阈值 96）。

## 边界

- 不做 OTA
- 不做平台（商店 / 账号 / 排行 / 审核）
- 不做历史记录
- 短按 = 游戏菜单，长按 = 退出
- 骰子搬进设备
- 中文菜单标题
- 退出后不做宠物反应
- 游戏是数据包，加游戏不刷固件
- 俄罗斯方块往后放，不做

实现上的既定选择：

- 钓鱼的「张力」用能力表里的 `gauge`（value + target + tolerance）表达
- 中文点阵 12×12，字号与阈值见「中文点阵」一节
- 局部刷新走 SPI 直刷，不做整屏重绘；LCD 无残影
- 菜单由引擎画（`firmware/main/game/game_menu.c`），不复用服务端那套卡片渲染
