# ai-agent-pet

**给 AI agent 装一张脸。**

一块 ESP32-S3 屏摆在桌上。AI agent 干活的时候它在旁边打工人，等你批准的时候它举起牌子。

![设备屏上的六种表情](images/screen-states.png)

*屏上就是这些画面 —— 由服务端用 Pillow 渲染成 240×320 的 JPEG 推给设备，
不是预先烧进固件的静态图。*

**三件事，这个项目替你扛了**：

- **数据不上云** —— 没有账号、没有登录、没有多租户。你的会话只留在你自己机器上的 petd 里
- **加功能不用刷固件** —— 屏幕只是个哑终端，业务逻辑全在服务端。改一行 Python、重启 petd 就生效
- **没有硬件也能先跑通** —— 仓库自带模拟设备，第一次试玩不用先焊板子

## 现在做到哪一步了

> 🟢 **服务端已落地并实测**（2026-11-04）。petd 订阅 OpenClaw gateway，把会话状态映射成宠物的表情，用 Pillow 渲染成 240×320 的 JPEG 推给设备。**310 项单测全绿**，CI 覆盖 Python 3.10 / 3.11 / 3.12。
>
> 🟡 **固件源码已在 CI 里真编译通过**（ESP-IDF v5.5），产出 `petd.bin` / `merged-binary.bin` / `uf2.bin`。但**还没在实机上验证过** —— 到货、烧录、上电、看到画面都还是未知数。

## 为什么

agent 在干活时是个黑盒。你不知道它在跑什么、卡在哪、是不是在等你点批准。这个项目把它的工作状态摆成一张脸：

- 跑工具时**埋头干活**
- 等你审批时**举起牌子**（最醒目的一个状态）
- 任务完成时**晃一下**
- 出错时**愣住**

外加一个旋转编码器：转它翻内容卡，按住并旋转切信息密度，长按强制刷新，短按摇个骰子。

## 三个硬约束（决定了整个架构）

1. **脑子在 Pi，屏幕是哑终端** — 业务逻辑全在 petd，设备端只做「收帧显示 + 按键上报」。改功能不用刷固件。
2. **设备端零中文字库** — 所有文字由 petd 用 Pillow 渲染进 JPEG。240×320 的屏放不下一套中文字库，也没必要。
3. **设备不直连 gateway** — 设备只认 petd，petd 才认 gateway。设备不持有任何 gateway 凭据。

## 架构

```
┌──────────────────────┐   WS :18860    ┌───────────────┐   WS :18789   ┌──────────┐
│  ESP32-S3             │ ────────────▶ │     petd      │ ────────────▶ │ gateway  │
│  ├ ST7789 2.4" 240×320│ ◀──────────── │  (Pi, Python) │ ◀──────────── │          │
│  ├ KY-040 旋转编码器   │   JPEG 帧      │  状态映射     │   会话事件    └──────────┘
│  └ TJpgDec 流式直刷    │               │  渲染 / 插件   │
└──────────────────────┘               └───────────────┘
                                          ▲
                                          │ feature 插件
                          localtime · 天气 · 待办 · 番茄钟 · …
```

设备侧的渲染走 TJpgDec 的 MCU 流式直刷（16 行 line buffer，7.68KB），**不做全屏帧缓冲** —— 150KB 单块分配在 Wi-Fi 栈起来后有 OOM 风险。🟢

## 快速开始

### 没有硬件（先看看它长什么样）

petd 后面能跟一个模拟设备 —— 渲染出来的画面、旋钮手势、后台预览全是真跑出来的，只有那块屏是假的。

```bash
git clone https://github.com/GlacierFang/ai-agent-pet.git
cd ai-agent-pet
pip install -r requirements.txt

# 告诉 petd 你的 gateway token（从 ~/.openclaw/openclaw.json 的 gateway.auth.token 取）
export PETD_GATEWAY_TOKEN=xxxx

python3 -m petd --port 18860
```

另开一个终端，把模拟设备接上去：

```bash
python3 petd/tools/mock_device.py --host 127.0.0.1 --port 18860
```

打开 <http://127.0.0.1:18860/admin/> 看后台控制台。

> 💡 **第一次打开会先让你设一个后台口令**（只存 scrypt 哈希）。已经设过的话就是登录框。
> 想要完全敞开（仅限开发自跑）：`PETD_ADMIN_AUTH=off`。

### 真机（自己焊一块）

接线 → 烧录固件 → 设备连 Wi-Fi → 设备找到 petd → 看到宠物。
这五步见 [部署手册](docs/部署手册.md)。

## 状态语义速查

完整规则见 [状态语义](docs/状态语义.md)。

| gateway 实测字段 | 宠物状态 | 表现 |
|---|---|---|
| 无会话，或 `hasActiveRun=false` | `idle` | 闲置 |
| `status=running` 且 `hasActiveRun=true` | `working` | 埋头干活 |
| `permissionModePending=true` 或 `unread=true` | `waiting` | **举牌子（最醒目）** |
| `status=done` | `done` | 晃一下 |
| `status=error` | `error` | 愣住 |
| `isBackground=true` | *排除* | 后台会话不参与宠物状态 |

一个会话可能同时命中多条规则，**按 `waiting` > `error` > `working` > `done` > `idle` 取第一个** —— 等你批准最急，那是唯一会真正挡住你的事。

宠物反映的是**全部会话**，不是某一个：每个会话各自判状态，宠物取最急的那个，并带上归因（是哪个会话在起作用）和计数（`等你 ×2`）。

「睡着了」不靠空闲判定 —— 只有你配的睡觉时段到了才睡。空闲的时候宠物在轮播卡片里，一直醒着。

## 屏上能看到什么

**整屏互斥 —— 屏上永远只有一样东西**，两个层不会叠在一起：

- **宠物层**：宠物脸 + 一行状态 + 跟的是哪个会话
- **内容层**：一张 feature 卡片，闲置时轮播

内容卡长这样：

![一张内容卡](images/screen-card.png)

仓库自带的默认宠物在 `skins/default/` —— 六态各一张 240×320 PNG，
屏上任何一刻都可能是其中一态，所以六张缺一不可：

| 闲置 | 干活 | 等你确认 | 刚完成 | 出错 | 睡着了 |
|---|---|---|---|---|---|
| <img src="skins/default/idle.png" width="110" alt="闲置"> | <img src="skins/default/working.png" width="110" alt="埋头干活"> | <img src="skins/default/waiting.png" width="110" alt="举牌子，等你确认"> | <img src="skins/default/done.png" width="110" alt="晃一下，刚完成"> | <img src="skins/default/error.png" width="110" alt="愣住，出错了"> | <img src="skins/default/sleeping.png" width="110" alt="睡着了"> |

上面还飘着一层**一次性覆盖物**（骰子、功德飘字）—— 它盖住整屏或盖在脸上，
但不改宠物在干什么：骰子停了自动让路，飘字自己淡出。

宠物住在一张**背景**上 —— 独立于宠物形象，自己也能换、自己也能传：

![宠物住在背景上](images/screen-bg.png)

背景和宠物形象是解耦的：换宠物背景不动，换背景宠物不动。

内置内容卡：

| 卡片 | 内容 |
|---|---|
| 会话 | 正在跑的会话和它们的状态 |
| 通知 | 未读消息和等你授权的事 |
| 最近完成 | 刚做完的事 |
| 时间 | 当前时间 |
| 主机 | 运行 petd 的这台机器：CPU、内存、磁盘、温度、开机时长 |
| 天气 | 当前天气和温度（Open-Meteo） |
| 功德箱 | 累计功德数 |
| 赛博骰子 | 上次摇出的点数 |
| 相册 | 你传的照片，轮播到就换一张（最多 10 张） |

**信息密度三档**：简洁 / 标准 / 详细。卡上放多少字由它决定 —— 宠物大小不变。

### 屏上的玩具

不是宠物状态，不进六态语义表 —— 就是两样好玩的东西：

- **赛博骰子** —— 短按旋钮，整屏变骰子，滚 1.5 秒出结果，再按一下收起。
  宠物忙着或者睡着了不弹：有活先干活，睡觉别吵醒。

  ![赛博骰子](images/screen-dice.png)

- **功德箱** —— agent 每次真把活干完，飘一句「功德 +1」和一句程序员玄学短句，
  数字常驻屏角。计数落在 `config.json` 里，重启不清零。

### 相册

后台「宠物设定」里的一个功能。勾上它，宠物没事干轮播时，每转到相册一次
就换下一张照片。

- 最多 10 张，在后台「宠物设定 → 功能 → 相册」里传（JPG / PNG / WebP）
- 照片卡**整屏是照片** —— 没有宠物脸、没有文字，只有右下角「第几张 / 共几张」
- 照片在服务端烧进 JPEG 帧，固件不用改

## 旋钮

KY-040 旋转编码器。**手势语义表在服务端**，设备只报原始测量值 —— 改手势不用刷固件。

| 手势 | 默认语义 |
|---|---|
| 旋转 | 翻到下一张卡 |
| 按住 + 旋转 | 切换信息密度 |
| 长按 | 刷新会话状态 |
| 短按 | 摇骰子（赛博骰子） |

映射写在 `petd/data/gestures.json`，改完重启 petd 生效。详见 [旋钮](docs/旋钮.md)。

## 后台控制台

单页，原生 JS，挂在 petd 同一个端口的 `/admin/` 下 —— **不多开一个端口**。预览和设备屏幕看到的是同一份 JPEG 字节，不会出现「后台好看、设备上丑」。

| 页签 | 内容 |
|---|---|
| 我的宠物 | 宠物状态、设备画面预览、会话列表、当前宠物 |
| 宠物库 | 一只宠物一张卡，可新建、换六态图、设为当前 |
| 宠物设定 | 功能勾选 + 做事的节奏（停留时长、信息密度、睡觉时段） |
| 连接与诊断 | 连接状态、原始遥测、连接配置、诊断日志、旋钮手势 |
| 文档 | 仓库里的文档直接在控制台里读 |
| 使用说明 | 说明书：怎么用旋钮、屏上会看到什么、设备怎么装、后台能改什么 |

**没有账号、没有登录、没有多租户、没有云端** —— 一台硬件对一个 petd，petd 对你自己机器上的 OpenClaw gateway。你 clone 下来自己编译自己跑。

⚠️ 几条硬规则（详见 [硬件指南](docs/硬件指南.md)）：屏和编码器的 VCC 都接 **3.3V 不是 5V**；烧录时**只接 PC 不接充电头**（DevKitC-1 两个 USB 口的 5V 在板上相通）；**N8R8 是八线 Octal PSRAM**，配错固件会静默找不到 PSRAM。
